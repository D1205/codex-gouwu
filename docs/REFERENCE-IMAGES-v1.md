# 工程参考图 v1

参考图用于表达零件外形、孔位、结构和标注，随文字一起整理成工程需求。它增加视觉输入，不改变任务书、单位、来源、版本和人工审阅规则。实现位置为 `mechanical_app/reference_images.py`、`server.py`、`agent.py` 与 `ui/src/ChatPanel.tsx`；HTTP 字段见 [API-v1.md](API-v1.md)。本文记录实现协议，不将代码存在视作完整工作流验收。

## 上传与保存

可以在聊天输入区选择图片、拖入图片或粘贴剪贴板图片。上传成功后显示缩略图；发送时把图片 ID 与本轮描述一起提交。连续补充会继续携带当前参考图；从本次参考中移除后，后续请求不再发送该图，对话里的历史图片仍保留。

- 每次需求最多 6 张参考图；支持 PNG、JPEG、WebP，仅单帧。
- 原图单张不超过 8 MiB、20,000,000 像素。图片上传 JSON 最大 12 MiB，其余 POST 接口仍为 1 MiB。
- 服务根据实际内容解码，拒绝伪装格式、不可解码、动画或超限图片。
- 按 EXIF 方向纠正图像；长边超过 4096 像素时等比缩小；仅保留 RGB/RGBA 像素并重新编码为无元数据 PNG。
- 净化后的 PNG SHA-256 同时作为图片 ID，用于去重。原始字节不保存；公开的宽高、大小与 SHA 对应净化后的文件。

规范化文件与公开元数据分别保存到应用数据根目录的 `reference-images/<id>.png` 和 `<id>.meta.json`。上传名去除目录与控制字符，仅作显示。客户端只能通过登记 ID 引用图像，不能让服务读取本地路径或外部 URL；读取时重新验证文件归属、大小、SHA、格式和宽高。已登记文件被篡改时拒绝继续使用。

若首次上传在写入 PNG 后因元数据提交失败而中断，同图重试只在现存字节与本次重新净化的字节完全相同时补登记；不覆盖不一致的文件或损坏的已有登记。

## 实际模型输入与证据

`POST /api/interpret` 先验证 `image_ids`，然后将登记记录交给 `interpret_brief(reference_images=...)`。解释适配器再次验证 PNG 实际字节、SHA、大小及宽高，将其复制到本次 `evidence_dir/reference-images/<序号>-<id>.png`，设置只读标记，并在模型调用前后校验快照指纹。

Codex CLI 模式使用 `--image <快照路径>` 附加图像，文字提示经标准输入传入。API 模式将相同快照编码为 Chat Completions 的 `image_url` 图片内容，直接从后端发送至已选接口；关闭图片能力时明确拒绝图片请求。默认 DeepSeek 的真实图文请求已验证，见 [多模型记录](MODEL-PROVIDERS-VALIDATION.md)。文件名或旧任务不能代替图像内容。

多张图片按清单顺序传入，提示包含 ID、名称、宽高和 SHA。`input.json` 与结果的 `runtime.reference_images` 记录公开元数据及证据目录内的相对 `snapshot_path`，以追溯本次提交给模型的具体像素；API 密钥与 HTTP 图片 base64 请求体不写入这些记录。失败与超时按现有解释流程保留，不能回退为预录图像结论。

仅有图片也可以提交。服务会要求模型从参考图整理需求，描述可见结构并追问缺少的尺寸、单位、深度、贯穿关系和遮挡部分。整理图片本身不执行 CAD；仍需用户核对就绪任务后点击生成。

## 尺寸与来源确认

图像像素和比例没有可靠的物理比例尺；图中标注即使能识别，也只是待核对信息。模型提议的尺寸、数量、角度、公差和标准不能仅凭图片自动标为用户已确认。

1. 图片识别或推测值使用 `source_kind=derived`、`confirmed=false`，引用包含 `参考图[<id>]`；缺失尺寸保留 `null`。
2. 助手应展示识别值并追问。即使用户最初说“按图中标注”，首次读取仍须逐项展示并要求文字确认。
3. 用户明确写出数字、单位和对应含义后，这段原话累计到 `brief`，才可支持相应确认；已有修改基线中的已确认参数可以继承。
4. 本地适配器除提示规则外还约束图像来源：不具备可追溯数字原话、也不属于已确认基线的值，降为未确认派生值并补充问题。它不能单凭数字相同证明尺寸语义正确，用户仍需核对需求卡。
5. 参考图不能提升为权威 `cad/spec` 来源。图片中的文字作为参考数据处理，不是可以覆盖工程规则的指令。

聊天上下文只帮助理解前一轮追问和选项。允许的角色只有 `user/assistant`；助手建议不成为用户证据，确认数字仍需出现在累计的用户 `brief` 或已确认基线中。生成后继续执行原有几何检查、原生视图审阅和版本发布流程；图片识别不提供制造、强度或实机认证。

## 本轮验证

需求与图片适配器、上传/HTTP、上传中断恢复和复合参数追问的相关检查已通过；前端 TypeScript 与生产构建通过。本轮没有重新执行 CAD，浏览器读取了既有已发布模型。

一次真实浏览器请求完成了文件选择、上传、登记、CLI 图片快照和模型理解。测试图文件名及文字需求未透露结构，模型实际识别出右上削角、左侧三个竖排圆孔和矩形窗口，返回 `needs_input`；全部工程参数仍未确认。证据见 [浏览器流程](../results/image-chat-ui/report.json)、[真实模型结果](../results/image-chat-ui/model-result.json) 和结果内绑定的原始执行目录。

图片粘贴、拖拽、去重、大图预览、输入法回车、换行、刷新恢复、手机布局和原模型显示已在浏览器覆盖。后续补充与仅图片发送复用上述真实响应检查界面行为，未计作新的模型调用。追问精简与长历史限额另做了 [本地显示回放](../results/image-chat-ui/display-report.json)，确认参数值、来源和未确认状态保持；原始 21 条追问记录保留，精简后为 6 条中文问题。

这份验证覆盖合成工程参考图的特定结构，不等同于任意照片、遮挡结构或尺寸标注的识别准确率。CLI 传图方式与 OpenAI 官方的 [图片输入说明](https://learn.chatgpt.com/docs/image-inputs?surface=cli) 一致。
